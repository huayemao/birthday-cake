1년 전, 저는 [https://www.birthday-cake.online/](https://www.birthday-cake.online/) 웹 앱을 만들었습니다. 하지만 솔직히 말해 오랫동안 바람 부는 소리 인식은 그리 정확하지 않았습니다. 주변 소리를 무시하고 입김만 따로 구분해 내지 못했기 때문입니다. 실제 생일 파티 현장은 환호성과 웃음소리, 배경 소음이 뒤섞여 통제하기 어렵습니다. 케이크와 촛불을 겨우 꾸미고 화면에 들어가자마자 주변 소음 때문에 촛불이 저절로 꺼져 버리는 일이 잦았습니다. 게다가 기기마다 마이크 감도가 천차만별이라 작은 소리에도 꺼지는 기기가 있는가 하면, 아무리 세게 불어도 반응하지 않는 기기도 있었습니다.

이전에도 몇 가지 임시방편을 시도해 보았습니다. 케이크를 배치한 뒤 마이크 감지를 잠시 멈춰 두는 '잠금' 버튼을 추가하거나, 마이크 감도 슬라이더를 제공하기도 했습니다. 하지만 근본적인 해결책이 되지 못해 실제 사용 경험은 여전히 들쭉날쭉했습니다.

다행히 최근 업데이트에서 이 문제를 근본적으로 해결했습니다. 이제 앱은 사람이 입으로 바람을 불 때의 음향 특징을 정확히 포착하고 대부분의 주변 소음을 걸러냅니다. 적절한 감도만 맞추면 잡음 때문에 촛불이 실수로 꺼질 걱정 없이, 주인공이 가볍게 불기만 해도 자연스럽게 꺼집니다. 실제로 지하철이나 시끌벅적한 윈난대학교 학생식당에서 테스트해 보았을 때도 감도를 약간 낮추기만 하면 주변 소음에 흔들리지 않고 기대대로 안정적으로 작동했습니다.

문제를 해결한 방법은 의외로 단순했지만 결과는 매우 효과적이었습니다. 실제 바람을 부는 오디오 샘플 여러 개를 직접 녹음해 Code Agent에게 전달하고, 주파수 영역과 시간 영역의 특징을 분석하게 한 뒤 이를 기준으로 음성 인식 알고리즘을 전면 재작성한 것입니다. 초기에 개발할 때는 말로만 AI에게 부는 소리의 특징을 설명해 코드를 작성했기 때문에 여러 번 수정해도 기기별 편차가 컸습니다. 이번에는 Antigravity IDE에서 최신 Gemini Neon 모델을 활용해 다시 작성했습니다. 이전 모델로 같은 결과를 낼 수 있었을지는 모르겠지만, 아무리 뛰어난 '인재'라도 질 좋은 컨텍스트와 실제 데이터가 뒷받침되어야 한다는 점을 깊이 느꼈습니다. 실제 오디오 샘플 없이 자연어 설명만으로는 AI의 이해에도 분명한 한계가 있습니다.

물론 디버깅 과정이 순탄치만은 않았습니다. 새 알고리즘을 적용해 제 노트북에서 처음 테스트했을 때, 아무리 세게 불어도 반응이 없는데 오히려 말소리가 감지되었습니다. Windows 기본 녹음기로 확인해 보니 마이크가 애초에 바람 소리를 녹음하지 못하고 있었습니다. 원인은 Windows의 '오디오 향상(Audio Enhancements)' 기능이 입김을 바람 소음으로 간주해 전부 제거해 버렸기 때문이었습니다. Windows에서 비슷한 문제를 겪으신다면 **설정 → 시스템 → 소리 → 속성(마이크 배열) → 고급 설정**에서 **오디오 향상**을 꺼 두시면 됩니다.

2. **실시간 음파 시각화 피드백**: 케이크 화면에 실시간 음파 표시를 추가했습니다. 대화 소리, 생일 축하 노래, 박수, 약한 바람 등 모든 소리에 실시간 파형이 반응하므로 사용자가 "앱이 소리는 듣고 있지만, 바람 부는 소리가 아니라고 판단하고 있다"는 상태를 직관적으로 확인할 수 있습니다.
