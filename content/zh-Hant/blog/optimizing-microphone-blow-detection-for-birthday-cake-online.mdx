一年以前，我開發了 [https://www.birthday-cake.online/](https://www.birthday-cake.online/) 這個 web app，但不得不承認，一直以來，對吹氣聲的識別非常不精確，無法做到單獨識別吹氣聲而忽略其他聲音。要知道，真正過生日的現場其實很難控制環境：周圍既有大家的歡呼說笑，也有背景噪音。經常是剛把蛋糕和蠟燭布置好，一進場景，蠟燭就被周圍的嘈雜聲直接誤判「吹滅」了。再加上不同裝置的麥克風靈敏度千差萬別，有的裝置一有風吹草動蠟燭就滅，有的卻怎麼費勁吹都沒反應。這些問題導致體驗大打折扣，很難在不同裝置和現實場景下穩定發揮作用。

之前我也嘗試過不少治標的方法：例如加一個「鎖定」按鈕（布置完蛋糕後先鎖住麥克風偵測，等壽星真正準備吹蠟燭時再解鎖），或者提供麥克風靈敏度滑桿。但這些設計始終沒從根本上解決問題，實際用起來，體驗依舊不穩定。

![吹蠟燭 app birthday-cake.online 中，蛋糕場景支援鎖定以暫停偵測麥克風，防止蠟燭意外熄滅](https://huayemao.run/api/files/64ad60dc2fb66d47.webp)

而在最近的版本中，這個問題終於得到了徹底解決。現在的 App 能夠精準識別人聲氣流中的吹氣特徵，並最大程度忽略其他雜音。只要調好合適的靈敏度，既不用擔心蠟燭意外被噪音熄滅，壽星也能輕鬆一吹即滅。實測下來，即便是在捷運裡、在雲南大學嘈雜的食堂中，只要把靈敏度適當調低，App 也能穩定按預期運作，不再受環境噪音干擾。

![在虛擬生日蛋糕 app birthday-cake.online 中，布置蛋糕時可調節麥克風靈敏度](https://huayemao.run/api/files/fc05e31fbc6fb544.png)

我解決這個問題的方法聽起來其實很簡單，卻最終證明十分有效——我直接採集了幾段真實的吹氣音訊，交給 Code Agent 分析這些音訊的頻域與時域特徵，以此為基準重寫聲音識別演算法。最早開發時，我只是單純用文字向 AI 描述吹氣特徵讓它寫演算法，結果經過多輪除錯，在不同硬體環境下的表現還是很不穩定。這次是在 Antigravity IDE 中借助最新的 Gemini Neon 模型重寫的；老實說，我不確定較早的模型能不能達到同樣的效果，但我深感：即便是頂尖的「人才」，也必須給足高品質的上下文與素材。不餵真實音訊樣本，光靠自然語言描述，AI 的理解深度終究有限。

當然，除錯過程也並非一帆風順。演算法改好後，我在自己的筆電上做初測，發現怎麼吹氣都沒回應，反而是說話聲會被偵測到。我打開 Windows 內建的錄音機一測，才發現麥克風根本就收錄不到吹氣聲——原來是系統的麥克風「音訊增強」功能在作怪，直接把吹氣聲當成背景風噪全給過濾了。如果在 Windows 上遇到類似情況，需要在 **設定 → 系統 → 音效 → 內容（麥克風陣列）→ 進階設定** 中，將【音訊增強】調整為關閉即可。

![在 Windows 中關閉麥克風的音訊增強以取消降噪](https://huayemao.run/api/files/9376f8328df3534c.webp)

除了重寫底層偵測演算法，這次更新我還加了兩個關鍵細節：

1. **吹氣錄音採樣校準**：使用者在配置環節可以錄製一段當前環境的簡短樣本，讓 App 動態分析當前的底噪與有效吹氣特徵，針對性完成校準。
    ![吹蠟燭 app birthday-cake.online 中支援吹氣錄音採樣校準](https://huayemao.run/api/files/d247ef9715a40b1f.png)
2. **即時聲波視覺化回饋**：場景內增加了環境聲波的動態顯示。無論是說話、唱生日歌、鼓掌還是微弱的氣流，介面都會有即時的波形回饋，讓使用者清楚看到「系統聽到了聲音，但判定它不是吹氣」，直覺區分識別狀態。

如果你正好需要一款能可靠識別吹氣聲、不掉鏈子的線上吹蠟燭 App，不妨試試 [https://www.birthday-cake.online/](https://www.birthday-cake.online/)，這次的體驗應該不會讓你失望。
